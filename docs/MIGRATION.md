# 迁移依据与改动

来源为已存在的本地 codebuddy-workflow V2。原始文件 SHA-256 见 migration-manifest.json；不包含用户名、原项目绝对路径、密钥或历史任务日志。封装只读来源代码，不修改原配置、认证和业务副本。

复用：scheduler.py 的任务 schema、Git archive 独立仓库、范围检查、替换编码保留、进程超时、JSON 解析、固定验收、单次返工、任务锁与日志；model_policy.py 的账号目录证据与路由；benchmark.py 的评分、配对 bootstrap 和保守推荐；audit/manage_models 的 ACP 发现与 probe；十任务生成器、37 项测试、演示业务的8项断言。

改造：移除写死的 Node/CLI/用户路径，改包内导入、外部状态目录、跨平台进程参数；保持 scheduler 模块以减少无关拆分。倍率阈值可显式配置，默认仍严格 <0.2，原“上限不可提高”测试改为非法阈值拒绝并增加可配置测试。基准绑定包内 scheduler 哈希，不再要求配置旁有源码。统计按实际功能检查数量计算，不硬编码为3。

修复：原实现对缺失 observed model identity 仍放行，封装改为必须与请求模型精确一致；缺失身份立即失败。发给模型的 task 不再附带仓库绝对路径和宿主测试可执行路径。原 ACP Windows 专属 CREATE_NO_WINDOW 改为平台条件。追加对应测试。

新增：独立 CLI/config/doctor、可搬迁 Skill 运行包、归属哈希安装/更新/卸载、真实任务统计、单元测试编写测评、敏感信息检查、双语文档、CI 和模板。

实测基线为37项（18调度+19模型/测评），不是只有18项；原8项是演示项目 unittest 业务验收，初始缺陷版本预期失败。旧测评结果不导入新账号/新版本路由，避免借用历史成绩。
